# CnTrainHub · 中国铁路网络可视化

Vite + Leaflet + Three.js + 原生 JavaScript 实现的中国铁路干线可视化网页：暗色底图、线路生长动画、缩放分级显示、线路/车站/铁路局三维筛选、点击信息卡片，以及由代码生成的动车组 3D 编组。

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # 输出 dist/
npm run preview    # 本地预览构建产物
```

## 功能

| 能力 | 实现 |
| --- | --- |
| 暗色底图 | Leaflet `L.tileLayer` + 免密钥暗色瓦片，瓦片层用 `opacity` 压到 `#0a0a1a` 基调（不用 CSS `filter`，那会让每帧重新栅格化全部瓦片） |
| 初始视角 | `fitBounds` 到中国全境（含南海诸岛），滚轮缩放 + 拖拽 |
| 生长动画 | `requestAnimationFrame` + `L.Polyline.setLatLngs()`，按累计里程插值，逐条错开 100 ms，`ease-out` 收尾，重绘限帧 ~30fps；移动端、后台标签页与 `prefers-reduced-motion` 直接呈现完整线条 |
| 缩放分级 | `zoomend` 监听：`<6` 干线 + 省会主站；`6–8` 增加区域性线路与地级市主站；`>8` 全部线路、车站与站名标签 |
| 路网底图 | 两级 LOD：全国视图用 1132 条主干边（4.6k 顶点），放大后换 4181 条边（19.6k 顶点），均按视口裁剪 |
| 筛选面板 | 左上角半透明浮层：线路类型（高铁 G / 动车 D / 城际 C / 普速 K·Z·T）、**车站等级（省会 / 地级市 / 县级）**、18 个铁路局，每项带真实计数，任一变化即时重绘 |
| 悬浮反馈 | 鼠标靠近线路 14 px 内即加粗（`weight + 2.4`）、指针变手、光标旁跟随名称提示；命中判定独立于车站，不会被附近车站抢走 |
| 信息卡片 | 线路 / 车站 / 铁路局 / **单条铁路边**均可点击出卡片，300 ms 淡入 + 上滑，随地图平移保持锚定；点击空白、`✕`、`Esc` 关闭；移动端转底部抽屉 |
| 点击容差 | 命中判定在地理空间按"屏幕像素半径换算公里"计算（线路 14 px、车站 11 px、边 6 px），细线不再需要精确点到 |
| 线路发光 | `filter: drop-shadow(0 0 3px currentColor)`，颜色由 `.rail-line--{family}` 类的 CSS `color` 提供（命名线路走 SVG 以保留该效果，重量级图层走 Canvas） |
| 响应式 | ≤768px 面板改为可收起抽屉、卡片转底部抽屉、隐藏次要按钮、不自动拉取大体积路网 |
| **3D 展示** | 路局卡片里带 **3D** 角标的车型行可跳 `detail.html?model=…`：Three.js 全屏场景、**7 款哈尔滨局车型**的程序化车体（CR400BF-G/GZ/GS、CRH5A/G、CRH380BG、CR200J3-C，各有独立头型与涂装）、雪昼/寒夜/影棚三主题、填方路基与两侧城市楼群、36 项常驻控制台、前进停止与合成环境音 |

线路配色：高铁 `#e63946`、动车 `#f4a261`、城际 `#f7b955`、普速 `#457b9d`。

## 性能：做了什么，以及怎么量的

**踩过的坑**：最初用 puppeteer 连续 `mouse.move` 拖图并数 `requestAnimationFrame` 帧，得出"33 → 53 fps"的结论。这个探针是错的——帧数被 CDP 事件往返吞吐主导，同一构建连续测量能从 36 fps 一路"涨"到 233 fps。改用**页内 rAF 自驱动平移 + 交错重复测量**后，真实结论小得多：

| 场景（页内驱动平移，3 次交错取中位） | fps |
| --- | --- |
| 全部图层开启 | ~48 |
| 关闭路网底图 | ~54 |
| 关闭车站层 | ~51 |

即底图约 9% 帧率、车站约 4%，中位帧时 16.7 ms（60 fps），p95 33 ms。跨版本对比在该无头环境下噪声过大（同一构建 22–60 fps 波动），因此**不给出"快了几倍"的数字**；可复现的测量脚本思路见上，请在自己的机器上以右下角实时 fps 为准。

结构上确实有效的改动：矢量层全部离开 DOM（2574 个车站从 `divIcon` 改为 Canvas 圆点）、按视口裁剪、路网两级 LOD、静态矢量 pane 加 `will-change: transform` 使其成为独立合成层、瓦片层不再挂 CSS `filter`。代价最大的一项（12 445 条边的详细路网）改为缩放 ≥ 8 才自动加载。

## 关于底图：CartoDB Dark Matter 已不再免密钥

需求中指定的 `https://{s}.basemaps.cartocdn.com/dark_all/{z}/{x}/{y}{r}.png` 现在对无密钥请求返回 **`API KEY REQUIRED`** 水印瓦片（`dark_nolabels` 与 `cartodb-basemaps-*.global.ssl.fastly.net` 旧域名同样如此），已不能"免密钥直接使用"。

因此默认底图换成同样免密钥、同为暗色的 **Esri World Dark Gray Base**，并保留一行切换：

- 默认：`http://localhost:5173/`
- 对比 CARTO：`http://localhost:5173/?basemap=cartoDark`（自行申请 CARTO key 后，把 `src/main.js` 顶部 `BASEMAPS.cartoDark` 的 URL 换成带 key 的地址，并将 `BASEMAP` 常量改为 `'cartoDark'`）

底图配置集中在 `src/main.js` 的 `BASEMAPS` 常量里。

```
src/detail-audio.js        WebAudio 合成运行环境音（风噪/轰鸣/轨缝节律）

src/data.json              3D 车型配置（编组、车长数组、尺寸、受电弓车厢；model 为车体构建器键）
src/trains.js              动车组侧视 SVG（symbol/use + 贝塞尔车头）与配属表
src/style.css              深色科技风、发光、卡片过渡、悬浮提示、响应式
src/detail.css             3D 页样式
data/railways.json         31 条命名线路（真实 OSM 几何）
data/stations.json         2574 个车站（真实坐标 + 12306 电报码 + 三级等级）
data/railway-bureaus.json  18 个铁路局机关驻地与管辖范围
```

## 数据来源与许可

| 内容 | 来源 | 许可 |
| --- | --- | --- |
| 线路几何、路网底图、单条边属性 | `@railroute-ts/china` 2026.9.1（OSM 主干路网，12 445 条边，含 `km` / `gauge` / `electrified`） | 代码 MIT，数据 ODbL-1.0 © OpenStreetMap contributors |
| 车站坐标与英文名 | 同上（9 326 个车站） | ODbL-1.0 |
| 车站名称与电报码 | [12306 `station_name.js`](https://kyfw.12306.cn/otn/resources/js/framework/station_name.js)（3404 条记录，第 8 字段为所在城市） | 公开接口 |
| 省 / 地级市面、境界线 | [chinese-global-compliant-geodata](https://github.com/JayMuShui/chinese-global-compliant-geodata) `chn-level-1.json`、`chn-level-2.json` | MIT |
| 铁路局清单 | 参考 [60464/railwaymap](https://github.com/60464/railwaymap) 的管辖范围口径 | — |
| 底图瓦片 | Esri World Dark Gray Base（免密钥） | Esri 非商业许可，需保留署名 |

`data/*.json` 均由 `scripts/build-data.mjs` 生成，不是手工描点：

- **线路**按"端点 + 主枢纽途经点"在真实路网上逐段求最短路拼接，端点支持多个候选站名（例如 `南京` 与 `南京南`，后者在该 OSM 子图里连到断头碎片，直连会绕出 910 km）。结果只保留与官方里程比值落在 **0.8–1.35** 区间的线路：**40 条候选中 31 条通过**，9 条被自动丢弃并记录原因（兰新、厦深、郑渝、汉宜、滨洲、宁杭、沈丹、京雄等——OSM 该子图缺走廊或存在跨域绕行，例如嘉峪关→哈密无直连，最短路径会横穿全国）。宁可用全量路网底图呈现这些区域，也不画走向错误的命名线。
- **车站**：12306 的拼音与 OSM 站名匹配（含方向词与拉丁化差异，如 `Changsha South`↔`changshanan`、`Haerbin`↔`Harbin`），得 **2574/3404** 个有坐标站点；再用 `chn-level-2` 的地级市面做**点在面内判定**得到所属地级市与省份，据此分级：省会车站 509、地级市车站 400、县级车站 1665。拼音同形会错配（12306"大理"会命中台湾的 Dali 站），因此落点省份不在路局表内的匹配一律丢弃，并有 23 条同形歧义被丢弃。
- **路局归属**按省级映射推断，蒙东、豫南等交界地区存在跨局例外，已在数据 `metadata.bureauNote` 与卡片中说明。
- 几何经 Ramer–Douglas–Peucker 简化后保留 3–4 位小数。
- 里程对照（图示 / 官方 km）：京沪高铁 1368/1318、京广高铁 2437/2298、沪昆高铁 2311/2252、哈大高铁 1108/921、成渝高铁 340/308、西成高铁 762/643、京津城际 162/150、陇海铁路 1659/1759、大西高铁 860/859。卡片同时展示"线路里程（官方）"与"图示路径"，不混为一谈。


## 每条铁路都有卡片

- **命名线路**（31 条）：开通年份、设计时速、官方里程、图示路径、端点、运营主体、途经主要城市。
- **车站**（2574）：省份、所属铁路局集团、车站等级、途经的命名线路、12306 电报码、坐标。
- **铁路局**（18）：全称、机关驻地、管辖范围、境内车站数与经过干线数。
- **单条铁路边**（12 445）：缩放 ≥ 8 后详细路网自动加载，点击任意区段即显示该边的真实属性——区段长度（km）、轨距、是否电气化，以及按几何判定的归属线路（含距离，阈值 5 km）；找不到就明确写"数据源未提供该边名称"，不编名字。

数据源本身不含线路名称表（`@railroute-ts/china` 只保留几何与 `km/gauge/electrified`），因此命名线路目录是人工整理的。本机访问维基百科与百度百科均失败（超时 / 反爬空页），所以**没有把无法核实的条目补进目录**；若你有权威名录（如国铁集团《铁路线路名称表》），可作为数据源接入 `scripts/build-data.mjs` 的 `LINES`。

车次信息可再接 [HerbertHe/cr-12306-train-info](https://github.com/HerbertHe/cr-12306-train-info)：其 `trains` 列表按车型与停靠站给出，可为卡片补"途经车次数量"——此前该字段是演示值，已删除而非保留假数据。

## 动车组侧视图（代码绘制）

`src/trains.js` 用内联 SVG 画各型号侧视剖面，不引用任何图片：

- **`<symbol>` + `<use>` 复用标准车厢**：`<defs>` 里定义一节 `<symbol id="car-*" viewBox="0 0 116 64">`，`<rect>` 画车顶/车身/车窗带/裙板、`<circle>` 画轮对、`<line>` 画车厢连接处；编组用 `<use href x y width height>` 按固定间距横排，加一节车厢只多一行。
- **车头单独用 `<path>` + 三次贝塞尔**：鼻锥是唯一能识别型号的形状，不做 symbol。三种壳形 `pointy`（CRH380A / CR400 系）、`round`（CRH2 / CRH5，新干线与潘多利诺后裔）、`boxy`（CRH1 / CRH3，Regina 与 Velaro 平台），车尾用 `scale(-1,1)` 镜像。
- **`<linearGradient>`** 做车身金属渐变、车窗玻璃反光、腰线渐变；全部整数坐标；**背景透明**；**不使用 `<filter>`**（部分浏览器对带 filter 的 SVG 渲染空白）。
- 卡片里画的是 4 节缩短编组（真实编组数以文字标注），因为 8 节缩到卡片宽度就看不清鼻型了。

13 个视觉基型 + 后缀变体，共 45 个型号（见下"型号库与配属"）。

点击地图上的**铁路局菱形**，卡片下半部即列出该局配属车型、配属数量及其侧视图。菱形按半径分区：正中约 5 px 归其下的枢纽车站，外圈归路局——否则路局标记（16 px）会把枢纽站完全盖住，两个目标至少有一个点不到。

### 型号库与配属

`TRAIN_MODELS` 共 **45 个型号**，由 13 个视觉基型（CRH1A / CRH2A / CRH3A / CRH3C / CRH5A / CRH380A / CRH380B / CRH380D / CR400AF / CR400BF / CR300AF / CR300BF / CR200J）加后缀变体生成——变体与基型共用壳形与涂装（现实中也是如此），因此新增变体只加一行索引，不重复绘制：

| 后缀 | 含义 | 后缀 | 含义 |
| --- | --- | --- | --- |
| `-A` / `L` | 16 辆长编组 | `-G` | 高寒型 |
| `B` / `BL` | 17 辆超长编组 | `-GS` / `-GZ` | 高寒 · 技术提升 / 智能 |
| `-Z` | 智能配置型 | `-S` / `-AS` | 技术提升 |
| `-AZ` / `-BZ` | 长编组 · 智能配置 | `E` / `G` | 卧铺 / 抗风沙高寒 |
| `-C` | 智能配置（京张·京雄） | `1-x` / `3-x` | 动力集中代际与编组 |

编组文本按型号显式给出，不靠后缀通用规则：`CRH3A-A` 是 8 辆城际型（后缀 `-A` 在这里不表示长编组），`CRH380BG` 是 **8 辆 4M4T 高寒短编**（16 辆的是 CRH380BL），CR200J 系列是"动力集中 · 机车+拖车"而非固定辆数。

侧视图还单列了 `CR200J3C` 基型（`drum` 头型 + 白/墨绿/中国红配色）：2022 年后的 CR200J3-C 采用"AD钙"新涂装，与 2019 年"绿巨人"的绿底黄腰线不是一套配色，共用旧基型会把卡片画错。

配属表 `BUREAU_FLEETS` 采用项目方整理的 **2025 年至 2026 年初公开报道**数据，含每局车型清单与配属数量（北京局 344、上海局 933、广州局 466.5、成都局 517、济南局 260、武汉局 258、郑州局 199.5、西安局 189、沈阳局 187、南昌局 206、哈尔滨局 115、昆明局 120、南宁局 170、兰州局 86、乌鲁木齐局 53、呼和浩特局 51，合计约 4155 组）。卡片底部固定展示三条口径说明：

- **统计口径**："标准组"按 8 辆 = 1、16/17 辆 = 2 折算，部分局直接以"组"计（字段 `unit` 区分）。
- **动态变化**：数量随新线开通与车辆调配持续变化，不是官方现车表。
- **未覆盖项**：太原局、青藏集团未在本次表中，沿用前次公开资料整理并标注；南昌局仅福州动车段数据。

车组号级实时配属需查 EmuSearch 等专业库；本项目未抓取（本机亦不可达），界面已注明该指引。

> 型号本身的涂装/原型/速度为公开资料：CR400AF 银灰车身红飘带（中车四方）、CR400BF 金飘带（长客/唐车，"金凤凰"）、CR200J 绿色动力集中（"绿巨人"，160 km/h）、CRH380D 为庞巴迪 Zefiro 平台、CRH5E 为卧铺动车组。

## 3D 展示页（Three.js）

入口：点开某个铁路局的卡片 → 配属车型列表里带 **3D** 角标的那一行会跳到 `detail.html?model=…`。哈尔滨局 7 款配属车型全部可看；未知车型走兜底页并列出全部已建模车型。

### 七个车型，四套车体

### 场景

| 项 | 值 |
|---|---|
| 主题 | 雪昼（默认）/ 寒夜 / 影棚三套，各自带天空渐变、雾色、地面色、主光与轮廓光参数；影棚沿用早期中性灰棚值 |

| 路基 | 填方梯形棱柱（顶宽 13.6 m 承两条线路+接触网杆，1:1.5 边坡落到 -3.4 m 地面）+ 基床表层与两侧电缆槽；取代早期那块悬空薄板 |

### 控制台

右侧常驻面板，全部即时生效，共 36 个控件：演示速度、加速度、8 节编组定位条（点某节车镜头平移过去）、7 个机位预设、环绕角/距离/高度/视野、自动环绕、主题、主光强度与方位、轮廓光、雪量、雾浓度、曝光、升弓、车灯、接触网、邻线、林木、城市楼群、楼群密度、楼宇高度、线框、画质，以及重置 / 随机 / 导出 PNG。左下角是数字速度表与里程，顶部是环境音开关。

环境音由 WebAudio 合成（风噪 + 低频轰鸣 + 按 12.4 m 轨缝节律的撞击声），音量与音高绑在车速上，停车即静音；首次用户手势后才创建 `AudioContext`。

### 车体怎么来的

3D 车体不来自 GLB，也没有 Blender 管线。`src/train-3d.js` 在运行时用 Three.js 生成整车：

| 部件 | 做法 |
|---|---|
| 车身 | 同一条 26 点截面环沿纵轴放样；车头 9.2 m 鼻锥段按实车侧影/平面取形：宽度 `0.34+0.66·sin(t·π/2)^0.8`（早早鼓起、鼻尖收宽圆弧），顶高 `1.2+2.85·sin(t·π/2)^1.05`（自鼻尖就上拱的平滑凸弧），避免细长针状鸟嘴；中间车两端 0.55 m 收口 |
| 涂装 | 3072×768 CanvasTexture，v 按高度分段映射把像素预算集中在侧墙。**CR400BF-GZ 走"龙凤呈祥"**：银灰金属漆 + 国旗红/故宫红/祥龙黄三色起伏飘带，**波峰上边界拱到车窗上沿之上**（先画飘带、再盖黑窗带，金飘带贴红带波峰上缘平行扫过），一节车一个完整正弦周期（0..2π）、波峰在车头/车厢前四分之一（基准相位 π，交替车反相）带尾焰分支 + 金色"复兴号"；G / GS 走"金凤凰"金色腰线。中间车两份相位相反的贴图交替，飘带在列车间连续流动 |
| 玻璃 | 侧窗、门玻璃是独立网格；司机室侧窗为**由后至前逐渐变窄**的黑色楔形（后缘高、前缘收尖），与风挡之间留银白车身隔带并压红/金/白细线（非整片黑）；风挡是贴鼻锥上表面外扩 2.4 cm 的曲面玻璃。寒夜下侧窗带暖色内透光 |
| 底架 | 薄地板 + 分段裙板 + 格栅，转向架处断开；构架 + 轮对 + 轴箱 + 一系弹簧，轮径 0.92 m 落在轨面 |
| 车顶 | 通长空调罩 + 3 个机组 + 天线；第 3、6 节受电弓可升/降两套几何切换，升弓滑板 5.38 m 贴住 5.4 m 接触线 |
| 编组 | 1 头 + 6 中 + 1 尾，尾车绕 Y 转 180°；节间 1.036 m 用风挡 bellows 填实；按材质合并，头车/中间车 A/中间车 B/玻璃/风挡/裙板/转向架/车顶/受电弓/头尾灯各一个 mesh |

尺寸按参考：车头 25.85 m、中间车 25.0 m、节间 1.036 m，全长 `2×25.85 + 6×25.0 + 7×1.036 = 208.95 m`，宽 3.36 m、高 4.05 m，轨顶面 y=0。

其余四个车型共用同一套"截面环放样 + UV 高度分段 + Canvas 涂装镜像到另一侧"的管线，但**每个平台有自己的截面轮廓、鼻型函数、窗/门布局、涂装绘制函数与材质色**：CRH5 是上窄下宽的鼓形窄车体 + 短钝楔形鼻，CRH380B 是低伏长鼻 + 圆形车钩罩，CR200J 是 4.15 m 高的鼓形客车 + 斜面司机室。编组由 `cfg.carLengths` 逐节给出，构建器回传每节车的世界坐标中心供镜头定位；受电弓车厢由 `cfg.pantoCars` 指定，控制台的编组定位条据此标出弓车。四个车型各用 3 张车涂装贴图，其余几何按材质合并，和 CR400BF 一样是一位数量的 mesh。

### 开销实测

- 雪昼默认视角每帧：CR400BF 系列 **30 次 draw call、39,454 三角面**，四个新车型 **32 次 draw call、38,694–40,402 三角面**，均为 **8 张纹理**（3 张车涂装 + 2 张楼立面 + 环境/雪/阴影），仍在 32 次 / 40,000 面预算内。
- 8 节车只上传一份头车车体和两份中间车车体，其余 `clone()` 后烘进合并几何。
- 切换主题会重建 PMREM 环境贴图并 `dispose()` 整个 render target，反复切换纹理数稳定在 6，不泄漏。
- 无头 Chrome + SwiftShader 软件栅格化，绝对帧率不作为验收条件；瓶颈是填充率而非面数。
- 回归验证（`.cache/gz-verify.mjs` / `gz-nav.mjs` / `gz-prod.mjs` / `hlj-models.mjs` / `hlj-regress.mjs` / `hlj-prod.mjs`）：8/9 节编组、开销预算、前进加速与 3.4 m/s² 减速归零、`target.y≈2.2`、中键旋转改变画面而右键不改 target、未知车型兜底列出 7 款车型、雪昼/寒夜/影棚切换、线框与降弓、机位预设与编组定位、390×844 竖屏、从哈尔滨局卡片看到 7 条 3D 行并可跳转到 CR200J3-C、生产包（调试钩子已 tree-shake）四车型启停与主题切换，全部通过且全程无 console error。

## 已知限制

- **车站等级不是官方评定**：省会 / 地级市 / 县级由"车站是否落在该地级市城区"推断（站名主体与地级市同名视为主站），用于视图分级，不等同于国铁集团车站技术等级。
- **路局归属为省级近似**：蒙东、豫南、苏北等交界地区存在跨局例外。
- **命名线路仅 31 条**：另有 9 条因 OSM 子图缺走廊而被主动丢弃（原因写入 `data/railways.json` 的 `metadata.droppedLines`）。这些区域由路网底图呈现，放大后可点击单条边查看真实属性，但没有名称与年份。
- **"途经车次数量"已移除**：该值此前是编造的演示数据；接入 12306 车次数据后再恢复。
- **配属数量与车型清单为整理值**：来自项目方汇总的 2025 年至 2026 年初公开报道，随新线开通与车辆调配动态变化；太原局与青藏集团未在该表内，沿用前次整理并已标注。车组号级实时配属需查 EmuSearch 等专业库（本项目未抓取）。
- **变体后缀语义按公开命名规律解释**（`-A` 长编组、`-G` 高寒、`-Z` 智能等），个别型号有专属含义时按型号显式覆盖，不套用通用规则。
- **3D 车体是程序化近似，不是工业级精模**：截面放样 + Canvas 涂装能保证比例、编组和主要特征（方肩圆顶车身、子弹头鼻尖、黑风挡、龙凤呈祥红金飘带 / 金凤凰腰线、司机室侧窗、受电弓），但雨刷、绝缘子、车门缝隙等细节是示意级别。
- **三款高寒型号共用同一套几何**：CR400BF-G / GZ / GS 按 `livery` 字段切换涂装（GZ 龙凤呈祥，G / GS 金凤凰），现实中的车顶设备与内装差异未单独建模。CRH5A 与 CRH5G 也共用头型与涂装——这不是偷懒，公开资料明确两者外观仅车钩整流罩有差别；2017 年换装全新流线头型的"CRH5G 技术提升型"没有单独建模。
- **四个新车型的涂装是程序化近似**：蓝腰线、蓝箭、AD钙红绿双弧、金色路徽与"CR / 和谐号 / 复兴号"字样按公开照片还原，车号小字为示意；前脸因截面放样 UV 在鼻尖退化为一条线，车钩罩、雨刷、路徽立体浮雕等只能做到示意级。
- **涂装是矢量近似而非实测色卡**：飘带波形、金色"复兴号"与红金配比按公开外观图还原，不是从厂修图纸取色；车号、座位等级标记等小字为示意。
- **受电弓为简化结构**：升/降两套静态几何切换，没有真实的升降机构与绝缘子串。
- **城市楼群是程序化体块**：四种楼型 + 可平铺立面贴图，按退距分近/中/远三排形成天际线；不是真实城市几何，楼内无结构、屋顶设备与街道细节为示意级别。
- **车钩与端部封盖**：节间用风挡 bellows 填实，但真车的车钩罩与风挡褶皱未单独建模。
- 底图瓦片与详细路网分别依赖 Esri 与 jsDelivr CDN；本机到这些域名的网络会间歇 `ERR_CONNECTION_RESET`，此时命名线路、车站与省界仍正常工作。
- 性能数字来自无头 Chrome（`--disable-gpu`，软件栅格化），绝对值偏保守且重复测量方差大；请以目标机器上右下角的实时 fps 为准。

## 哈尔滨线路漫游（journey.html）

第三个页面：`journey.html`，入口 `src/journey/journey.js`。地图页与车型展示页顶栏都加了「线路漫游」链接。它不改动那两页的场景逻辑。

### 一句话原理

**列车不动，世界往后跑。** 车头永远朝 -Z 停在原点，列车走过的真实里程 `travel`（米）就是唯一的时钟；线路按 400 m 切成块，只保留列车前 7 块 + 后 2 块，出窗口就摘掉。于是「哈大高铁 921 km」这样的线路，显存里永远只有约 4 km 的场景 —— 这就是按节点距离触发渲染，而不是做一张全量地图。

```
travel(真实米) ──► visibleChunks(route, travel, ahead, behind) ──► 只建这些块
                         │
                         ├─ 站区   → 真实站房 + 站台 + 雨棚
                         ├─ 车辆段 → 检修库 / 列检棚
                         ├─ 城区   → 哈尔滨风格楼群（InstancedMesh）
                         ├─ 地标段 → 教堂 / 纪念塔 / 大桥等
                         └─ 郊外   → 可循环的田地 / 河流 / 草地（不额外建几何）
```

每块的世界坐标是 `z = travel - chunkId × 400`：里程大于 travel 的在前方（-Z），等于 travel 的正在车边，小于 travel 的已到车后（+Z）。每帧只改几个 `Object3D.position`，不重算任何实例矩阵。

### 模块分工

| 文件 | 职责 |
|---|---|
| `src/journey/config.js` | 共享契约：经纬度→米投影、真实站点原点、分块/触发距离、三套主题、画质与预算常量 |
| `route-data.js` | 真实线路与节点（官方里程、设计时速、站点真实经纬度、累计 km） |

### 出发站 / 车底 / 编组

- **出发站**：顶栏第一个下拉按线路分组列出 8 条线上的 **115 个真实高铁站**（`optgroup` 分线路），选哪站就把 `travel` 设成该站的真实累计里程，从那里向线路终点方向跑；切线路会同步回到该线首站。不是「选一条铁路」，而是「选一个站上车」。
- **动车组**：控制台可换 7 款哈尔滨局车型（CR400BF-G / GZ / GS、CRH5A / G、CRH380BG、CR200J3-C），切换时 `dispose()` 旧车底再重建，涂装贴图与几何一并释放。
- **编组**：8 辆标准编 / 16 辆长编。逐节车长、受电弓车厢、全长都随编组重算：8 辆 200.65–232.4 m，16 辆 399.25–418.7 m（CRH380BG 的 16 辆 399.25 m 与 CRH380BL 官方 399.27 m 几乎一致）。CR200J3-C 实车是 **9 辆短编**，选「8 辆」时保留真实 9 辆并在界面注明，选「16 辆长编」按 1 动力 + 14 拖 + 1 控制示意重联；16 辆时机位自动后撤 1.45 倍才收得进画面。
- 换车底是高频操作，不重烘阴影贴图（`shadowMap.autoUpdate=false` 下每次重烘都会新建一张 RenderTarget）；主题 / 画质 / 线框 / resize 等低频操作才走 `refreshShadows()`。反复换 6 次车型，纹理数稳定在 9。

### 现实依据与口径

- 收录 8 条真实线路、合计 3877 km，末站累计里程严格等于官方运营里程（纯函数单测校验单调递增）：哈大高铁 921 km、哈齐高铁 286 km、滨洲铁路 935 km、滨绥铁路 548 km、哈佳铁路 336 km、哈牡高铁 293 km、京哈高铁哈长段 240 km、哈伊高铁 318 km。站点经纬度取自 `data/stations.json`（哈尔滨局 240 个真实站），资料来源（光明日报 / 人民网 / 国家铁路局 / 国资委 / 黑龙江省政府等 30 条 URL）写在 `route-data.js` 文件头。
- 里程**严格按真实公里**累加，官方运营里程锚定总长、相邻站球面距离按比例分配，口径写在 `route-data.js` 文件头；官方里程与 OSM 折线几何长度（如哈大 921 vs 1108 km）不混为一谈。
- 市区局部（哈尔滨站为中心 ±30 km）用真实经纬度等距投影摆站房、江面与地标；郊外不追求经纬度一致，只保证里程一致，用重复地形盖住。
- 站房/楼宇外观按公开报道与照片做**示意级复刻**（新艺术运动风格的哈尔滨站、陶板拱顶的哈西站、道外中华巴洛克、圣索菲亚洋葱顶等），不是工业精模，也不使用任何第三方图片/模型素材。
- "车管所"按铁路口径实现为**车辆段 / 动车段 / 机务段**。

### 性能

重复元素一律 `InstancedMesh`、同材质 `mergeGeometries`；枕木按 0.62 m、接触网柱按 20 m 周期取模平移；PMREM 环境贴图每主题烘一次并 `dispose()` 整个 RT；`shadowMap.autoUpdate=false` 只在主题/画质变化时重烘；画质三档封顶 pixelRatio。验收口径一如既往：**零 console error + draw call / 三角面 / 纹理预算**，无头 SwiftShader 的绝对帧率不作数。

调试钩子（仅 DEV）：`window.CNTHUB_JOURNEY()` 给出 `travel / km / chunks / chunkKinds / calls / tris / textures`，`.api.setTravel(米)` 可直接跳到任意真实里程核对分块内容。

**无头 Chrome 实测**（1440×860、SwiftShader）：起点站区 **34 次 draw call / 85k 三角面 / 9 张纹理**，市区最重 40 次 / 94k 面 / 11–14 张纹理，跑出市区后降到 **22–24 次 / 68k 面**；全程零 console error。控制在 `config.js` 的 `BUDGET`（64 / 140k / 18）以内。做法是同一站房/车辆段/地标在 10 块窗口里只实例化一次（挑离列车最近的块），每个城区块只放 1 类楼的 InstancedMesh。

**已知近似**：站房按「线侧站」摆放并略缩小（原型是跨线高架，若压在正线中心，13 m 高的英雄机位会钻进屋顶）；25 座精模站之外的 51 个沿线站自动降级为 3 类通用中小站模板；龙塔 / 大剧院 / 太阳岛 / 冰雪大世界无可靠测绘坐标，不编造经纬度，只按「江北 / 东南」大致方位在城区块轮换示意摆放；市区底图的河宽、路宽、面块均为简化多边形；郊外重复地形与经纬度无关，只对齐 400 m 里程周期。
